# Домашнє завдання — Воркшоп 3

**Тема:** Правила та команди: керована поведінка AI
**Формат:** налаштовуєте агента на реалістичному проєкті — правила, спільна база,
команди — і перевіряєте числами й спостереженнями, чи це працює
**Час:** ~1.5–2 години
**Здача:** Pull Request у starter-repo (CodeRabbit зробить рев'ю)

WS2 закінчився тезою «права надійніші за правила». Сьогодні — про те, як зробити
правила справді робочими: де вони живуть у Claude Code і Cursor, як їх писати, щоб
агент їх виконував, як перетворити повторювані дії на команди — і як перевірити,
що все це працює, а не лише заспокоює.

> 📊 **Рубрику опубліковано наперед** — розділ
> [«Як це оцінюється»](#як-це-оцінюється) перед Definition of Done.
> Прочитайте його **до того, як почнете**.

| | Claude Code | Cursor |

## Task A — Правила проєкту _(~35 хв)_

**Мета:** агент дотримується архітектури проєкту, а не вгадує її щоразу заново.

1. Прочитайте `materials/architecture-brief.md` (~5 хв). Це текст для людей —
   довгий, з історією й поясненнями. Правило для агента — коротке, конкретне й
   перевірюване.
2. Створіть **три правила** за шаблоном свого інструмента
   (`docs/templates/rule-claude.md` або `docs/templates/rule-cursor.mdc`):
   - **`architecture`** — шари й напрям залежностей; як додається нова інтеграція;
     публічний API ядра — що існує, а чого не існує;
   - **`conventions`** — `Result` замість винятків; `postJson` / `readEnv` /
     `parseJson` + guard / `log`; без `any`; без нових залежностей; жодних email і
     телефонів у сповіщеннях;
   - **`do-not-touch`** — `app/src/core/**`, `app/scripts/**`, `materials/**`,
     `.coderabbit.yaml`, `.github/**` — і що робити, якщо задача без змін у core
     не виконується.
3. **Режим застосування** обирайте свідомо:
   - `do-not-touch` — діє завжди (Claude Code: без `paths`; Cursor: `alwaysApply: true`);
   - `architecture` і `conventions` — прив'язані до `app/src/**`
     (Claude Code: `paths`; Cursor: `globs`).
4. У кожного правила — розділ **«Як перевірити»**: команда або ознака, за якою
   людина за хвилину скаже «виконано» чи «ні».
5. Швидка перевірка: у **новій** сесії попросіть агента, не відкриваючи файлів,
   перелічити правила проєкту, які вже є в його контексті.

> ⚠️ Захисне правило з винятком «якщо задача цього потребує» — не правило:
> будь-яка задача оголосить, що потребує. У `do-not-touch` замість «можна, якщо
> дуже треба» — «зупинись і опиши, що саме треба змінити в core».

**Перевірка:** три файли у правильній теці й з правильним розширенням; режими
застосування — як вище; у правилах конкретика з записки (імена функцій і шляхи),
а не «пиши якісний код».

## Task B — AGENTS.md як спільна база _(~15 хв)_

**Мета:** одна база, яку читають обидва інструменти, — без дублювання.

1. Перепишіть `AGENTS.md` (зараз там «пиши якісний код»). До ~60 рядків:
   - що це за проєкт — 2–3 речення;
   - команди: встановлення, тести, typecheck, `check:rules`;
   - карта: `core/` (захищене), `integrations/`, `sync/`;
   - 5–7 найважливіших правил — **одним рядком кожне**, з посиланням на детальні
     правила замість їх копії;
   - як перевірити роботу перед комітом.
2. Виправте `CLAUDE.md`. Зараз там **посилання** `[AGENTS.md](./AGENTS.md)`.
   Claude Code його **не імпортує**: агент бачить лише рядок тексту. Потрібен
   **імпорт** — окремий рядок:
   ```md
   @AGENTS.md
   ```
   Нижче можна дописати те, що стосується лише Claude Code.
3. Переконайтеся, що база справді завантажилась, і запишіть, як саме, у
   `docs/verification.md` (шаблон — `docs/templates/verification.md`):
   - Claude Code — `/context`, розділ **Memory files**;
   - Cursor — нова сесія: попросіть, не відкриваючи файлів, назвати команди й
     захищені теки проєкту.

> Навіть якщо працюєте лише в Cursor, `CLAUDE.md` виправте: в агенції будуть
> обидва інструменти, а база має бути одна.

**Перевірка:** `AGENTS.md` короткий і конкретний, не дублює правила дослівно;
`CLAUDE.md` містить `@AGENTS.md`; факт завантаження зафіксовано.

## Task C — Команди: API до агента _(~30 хв)_

**Мета:** повторювані дії — одним викликом і з однаковим результатом у всієї команди.

Створіть **три команди** за шаблоном `docs/templates/command.md`
(Claude Code — `.claude/commands/`, Cursor — `.cursor/commands/`):

| Команда | Що робить | Stop-правило, наприклад |
|---|---|---|
| `analyze-error` | Лог або стек → корінна причина: файл, рядок, механізм. Відрізняє **тригер** від **причини**. Пропонує тест, що відтворює проблему | Код не змінювати: звіт і план, чекати підтвердження |
| `refactor` | Приводить файл до конвенцій **без зміни поведінки**: тести й `check:rules` до і після | Лише вказаний файл і його імпорти; асерти в тестах не редагувати |
| `generate-integration` | Нова інтеграція за архітектурою: модуль, тест, рядок у реєстрі | Core не чіпати, нових залежностей не додавати, показати підсумок |

Кожна команда: `description` у frontmatter, ціль з аргументу, кроки,
**acceptance criteria** і **stop** — як промпт-артефакти з WS2. Посилайтесь на
правила, а не переписуйте їх у команду.

Потім **запустіть кожну** і запишіть у `docs/verification.md`, що сталося:

1. `/analyze-error materials/error-log.txt` — що агент назвав причиною нічного
   інциденту? Чи зупинився там, де сказано в stop?
2. `/refactor app/src/integrations/sheets-append.ts` — `check:rules` для файлу
   до → після, `npm test` до → після.
3. `/generate-integration <сервіс>` — будь-який сервіс, з яким працює ваша
   агенція: HubSpot, Pipedrive, Monobank, Telegram…

> 🔎 **Спостереження, а не віра.** Claude Code підставляє в `$ARGUMENTS` текст після
> назви команди. Для Cursor документація такого плейсхолдера не описує — тому
> рядок «Ціль» у шаблоні написаний так, щоб команда працювала в обох випадках.
> Запишіть, що відбулося саме у вашому інструменті.

> Корінну причину інциденту агент може знайти не з першого разу — це нормально.
> «Закінчилось місце на диску» — це **тригер**. Питання для причини: чому
> дублікати тривали ще дев'ять годин після того, як диск звільнили? Якщо команда
> зупиняється на тригері — покращіть її (наприклад, кроком «відрізни тригер від
> причини») і запустіть ще раз. Ця ітерація — теж частина роботи.

Фікс інциденту — за бажанням. Якщо додаєте тест, що відтворює проблему, то або
полагодьте код, або не комітьте падаючий тест: `npm test` у PR має бути зеленим.

**Перевірка:** три файли команд; у `docs/verification.md` — сліди трьох реальних
запусків.

## Task D — A/B-валідація правил _(~25 хв)_

**Мета:** перевірити, чи правила справді змінюють поведінку агента, — числами й
спостереженнями, а не враженням.

Запит у `materials/ab-task.md` навмисно такий, що «прямолінійне» виконання впирається
в захищене ядро. Саме тут видно, чи працює ваше `do-not-touch`.

1. Закомітьте Task A–C. `git status` має бути чистим. Створіть теку `docs/ab/`.
2. **Прогін B — без правил і без команд.** Перейменуйте:
   - Claude Code: `CLAUDE.md` → `CLAUDE.md.off`, `AGENTS.md` → `AGENTS.md.off`,
     `.claude/rules` → `.claude/rules.off`, `.claude/commands` → `.claude/commands.off`
   - Cursor: `AGENTS.md` → `AGENTS.md.off`, `.cursor/rules` → `.cursor/rules.off`,
     `.cursor/commands` → `.cursor/commands.off`

   > **Чому ховаємо й команди.** У Claude Code команда — це skill, і модель може
   > запустити його сама, без вашого `/`. У нашому пробному прогоні агент «без правил»
   > першим кроком викликав `/generate-integration` — і отримав з неї всі конвенції.

   Відкрийте **нову** сесію й вставте запит із `materials/ab-task.md` **без змін**.
   Нічого не підказуйте. Якщо агент зупиниться й спитає, як діяти, — відповідайте
   **однаково в обох прогонах**: «Роби, як вважаєш правильним».
3. Зафіксуйте результат (з кореня репо):
   ```bash
   npm --prefix app test
   npm --prefix app run check:rules
   git status --short
   ```
   Якщо агент змінив файли — збережіть діф:
   `git add -N app`, потім `git diff --output=docs/ab/b-rules-off.diff -- app`.
   Скопіюйте в звіт фінальну відповідь агента і приблизно — скільки файлів він
   прочитав, перш ніж щось вирішити (видно в журналі інструментів сесії).
4. Поверніть `app/` у стан до прогону й правила на місце:
   ```bash
   git reset -q
   git checkout -- app
   git clean -fd app
   ```
   Потім перейменуйте файли з `.off` назад.
5. **Прогін A — з правилами й командами.** Нова сесія, той самий запит, та сама
   відповідь на уточнення. Зафіксуйте те саме; діф — у `docs/ab/a-rules-on.diff`,
   якщо агент щось змінив.
6. Заповніть `docs/ab-validation.md` (шаблон — `docs/templates/ab-validation.md`).

> **Що вважати різницею.** Не лише `check:rules`. Чи змінив агент `app/src/core/`?
> Чи зупинився й спитав? Що запропонував зробити з core — і з самою перевіркою
> (`app/scripts/core.lock.json`)? Скільки кроків знадобилось, щоб зрозуміти домовленості?

> **Якщо різниці немає — це теж результат**, запишіть його чесно. Агент із високим
> рівнем міркування часто знаходить домовленості сам: в архітектурній записці, у
> коді перевірки, у сусідніх модулях. Запишіть, **звідки саме** він їх узяв. За
> бажанням повторіть прогін B, сховавши ще й `materials/architecture-brief.md`, — так
> виглядає звичайний клієнтський проєкт, де такої записки немає.

**Перевірка:** обидва прогони з одним запитом у нових сесіях; для кожного —
поведінка агента, числа `check:rules` і `npm test`, змінені файли; висновок
спирається на це.

## Task E (bonus) — хук замість прохання _(~15 хв)_

Правило **просить** агента не чіпати `app/src/core/**`. Хук — **не дає**.

- **Claude Code:** у `.claude/settings.json` — хук `PreToolUse` з matcher
  `Edit|Write`, що запускає `node .claude/hooks/protect-core.mjs`. Скрипт читає
  JSON зі stdin, бере шлях із `tool_input.file_path` і, якщо це `app/src/core/`,
  пише причину в stderr і завершується з кодом **2** — дію заблоковано.
- **Cursor:** у `.cursor/hooks.json` — хук `preToolUse` на тому самому скрипті.
  Код виходу 2 у Cursor теж блокує дію. Точну форму вхідного JSON подивіться в
  каналі виводу Hooks і, якщо треба, підлаштуйте, звідки скрипт бере шлях.

Перевірка: попросіть агента «додай коментар на початок `app/src/core/log.ts`» —
дія має бути заблокована. Цитату відповіді хука запишіть у `docs/verification.md`.

> Пишіть скрипт на Node, а не на bash: так він працює і на Windows.

## Як це оцінюється

Definition of Done нижче — це **залік/незалік**. Рубрика тут — це якість роботи
на 100 балів.

| Вимір | Балів | Що саме дивимось |
|---|---|---|
| **Правила проєкту** (Task A) | **30** | Три правила в правильному форматі й теці; режими застосування обрано свідомо (`do-not-touch` — завжди, решта — за шляхами); конкретика з записки: функції, шляхи, заборона разом з альтернативою; «Як перевірити» в кожного. |
| **Спільна база** (Task B) | **15** | Короткий конкретний `AGENTS.md` без дублювання правил; `CLAUDE.md` з `@AGENTS.md`; зафіксовано, що база справді завантажилась. |
| **Команди** (Task C) | **25** | Три команди з `description`, ціллю з аргументу, кроками, acceptance criteria і stop; у `docs/verification.md` — сліди трьох реальних запусків: причина інциденту, `check:rules` до/після рефакторингу, створена інтеграція. |
| **A/B-валідація** (Task D) | **25** | Один запит, дві нові сесії, у прогоні B сховані й правила, і команди; для обох — поведінка агента, числа `check:rules` і `npm test`; висновок спирається на спостереження — зокрема чесне «різниці немає» з поясненням, звідки агент узяв домовленості. |
| **Бонус: хук** (Task E) | **5** | Хук блокує зміни в `app/src/core/**`, і це підтверджено реальною спробою. |

### Що знімає бали

- Загальні фрази замість правил: «пиши якісний код», «дотримуйся best practices».
- Усе в режимі «завжди»: `alwaysApply: true` чи правило без `paths` там, де воно
  стосується лише `app/src/**`, — зайвий контекст у кожній сесії.
- Неправильний формат: `.md` у `.cursor/rules/`, `globs:` у `.claude/rules/`.
- `CLAUDE.md` з посиланням замість імпорту `@AGENTS.md`.
- `AGENTS.md`, що дослівно копіює правила, або правила, що суперечать одне одному.
- Виняток у захисному правилі («можна, якщо задача цього потребує»).
- Команда без acceptance criteria чи stop; команда, яку жодного разу не запускали.
- A/B з різними запитами, без нових сесій, без спостережень або з командами, лишеними
  в прогоні B.
- Зміни в `app/src/core/**`, `app/scripts/**` чи `materials/**` — це порушення
  саме того правила, яке ви пишете.
