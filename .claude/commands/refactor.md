# Refactor

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає шляху до файлу — він у повідомленні одразу після назви
команди. Немає й там — спитай і зупинись.)

## Кроки

1. Переконайся, що файл існує і не лежить у захищених шляхах із
   `.claude/rules/do-not-touch.md`: `app/src/core/**`, `app/scripts/**`, `materials/**`,
   `.coderabbit.yaml`, `.github/**`. Якщо лежить — зупинись: такий файл не рефакторять.
2. Зафіксуй базову лінію з теки `app/`: `npm test` і `npm run check:rules`; запиши
   кількість порушень саме для цього файлу.
3. Прочитай тести цього файлу: вони фіксують поведінку (URL, тіло запиту, тексти
   помилок). Це контракт, який не можна зламати.
4. Перепиши файл за `.claude/rules/conventions.md` і `.claude/rules/architecture.md`.
   Якщо змінюється експорт — онови місця використання.
5. Повтори `npm test`, `npm run typecheck`, `npm run check:rules`.

## Acceptance criteria

- [ ] `npm test` зелений до і після; асерти в тестах не змінено.
- [ ] `npm run check:rules`: у цільовому файлі 0 порушень, в інших файлах нових не з'явилось.
- [ ] Змінено лише цільовий файл і, за потреби, імпорти в місцях використання.
- [ ] Поведінка, яку фіксують тести, та сама.

## Формат відповіді

Таблиця «до → після» (порушення за правилами, тести); перелік змінених файлів;
зміни поведінки, яких тести не покривають (напр. «раніше падав на не-JSON — тепер
повертає Result»).

## Stop

Змінюй лише цільовий файл і необхідні імпорти в місцях використання. Проблеми,
знайдені по дорозі в інших файлах, — окремим списком, без виправлення.
