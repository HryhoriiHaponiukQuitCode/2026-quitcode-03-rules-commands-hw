# Generate integration

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає назви сервісу — вона в повідомленні одразу після назви
команди. Немає й там — спитай і зупинись.)

## Кроки

1. Зразок — `app/src/integrations/slack-notify.ts` і його тест. `sheets-append.ts` —
   спадщина, за зразок не брати.
2. Визнач kebab-назву (`<service>-<action>`), змінні середовища (лише імена),
   endpoint, формат запиту й форму відповіді. Чого не знаєш про API сервісу — не
   вигадуй: винеси це в явні припущення.
3. Створи `app/src/integrations/<name>.ts`: `export const <camelName>: Integration`;
   `readEnv` → `postJson` → за потреби `parseJson` з guard, оголошеним у цьому ж
   файлі → `log` → `Result<void>`.
4. Створи `app/src/integrations/<name>.test.ts`: успіх (URL і тіло), відсутня змінна
   середовища, помилка сервісу.
5. Додай інтеграцію в `app/src/integrations/index.ts`.
6. З теки `app/`: `npm test`, `npm run typecheck`, `npm run check:rules`.

## Acceptance criteria

- [ ] Змінено рівно три файли: модуль, тест, реєстр.
- [ ] `npm test` і `npm run typecheck` зелені; `check:rules` не показує порушень у нових файлах.
- [ ] Жодних змін у `app/src/core/**` і `app/package.json`.
- [ ] Якщо це сповіщення — у повідомленні немає email і телефону.

## Формат відповіді

Перелік файлів; змінні середовища, які треба додати в деплой; припущення про API
сервісу; результати трьох команд.

## Stop

Не створюй `.env`, не встановлюй пакети, не чіпай розклад запусків. Після зелених
перевірок — підсумок і чекай.
