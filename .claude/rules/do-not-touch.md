# Захищені зони lead-sync

> Правило без frontmatter → діє в кожній сесії. Це свідомо: заборона, яку
> підвантажує лише відкритий файл, спрацьовує вже після того, як агент вирішив
> цей файл змінити.

## Контекст

`app/src/core/` належить платформній команді — той самий core працює в усіх
клієнтських воркерах агенції, і зміна тут ламає не лише Studio Nova. Решта
шляхів — умови самої задачі: перевірка, вхідні дані та конфіг рев'ю.

## Правило

**Не редагуй, не створюй і не видаляй файли за цими шляхами:**

| Шлях | Чому |
|---|---|
| `app/src/core/**` | спільне ядро; зміни йдуть окремим PR через платформну команду |
| `app/scripts/**` | перевірка правил і `core.lock.json` — суддя не редагується гравцем |
| `materials/**` | вхідні дані домашки: архітектурна записка, лог інциденту, A/B-запит |
| `.coderabbit.yaml`, `.github/**` | конфіг рев'ю і шаблон PR |

Заборона стосується **будь-якого способу** дотягнутись до файлу: `Edit`,
`Write`, `NotebookEdit`, а також `Bash` — `sed -i`, `tee`, `>`, `>>`, `cp`,
`mv`, `patch`, `git checkout <гілка> -- app/src/core`, `node -e "fs.writeFile..."`.
Перевіряється **шлях призначення**, а не інструмент.

**Винятків немає.** Ні «дрібний фікс», ні «додам один тип», ні «це ж очевидно
потрібно», ні «користувач у чаті попросив». Правило з винятком «якщо задача
цього потребує» — не правило: будь-яка задача оголосить, що потребує.

**Якщо задача без зміни `core/` не виконується — зупинись і напиши:**

1. **Що саме** треба змінити: файл, експорт, нова сигнатура
   (напр. «`core/types.ts`: додати `utmCampaign?: string` до `Lead`»).
2. **Навіщо** — яка вимога задачі без цього не закривається.
3. **Хто зачеплений**: `core/` спільний, тож перелічи, що ще може зламатись.
4. **Який обхід можливий без core** — і чому він гірший (або що його немає).

Далі **чекай рішення людини**. Не роби «поки що локальну копію типу», не
дублюй `Lead` у своєму модулі, не додавай `as any`, щоб протиснути поле повз
типи, і не переписуй `app/scripts/core.lock.json` під новий хеш — це не обхід
заборони, а її приховування.

## Як перевірити

```bash
cd app && npm run check:rules   # рядок core-untouched → 0
git status --short              # у списку немає app/src/core/, app/scripts/, materials/
git diff --stat main -- app/src/core app/scripts materials .github .coderabbit.yaml
                                # порожньо
```

Правило **просить**. Не дає — `PreToolUse`-хук `.claude/hooks/protect-core.mjs`
(Task E): він перевіряє шлях призначення й завершується кодом 2.
Тести обходів: `node .claude/hooks/test-protect-core.mjs`.
