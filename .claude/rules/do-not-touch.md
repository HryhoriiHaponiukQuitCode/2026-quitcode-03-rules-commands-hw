# Do not touch — захищені файли

## Контекст

`app/src/core/` — спільне ядро всіх клієнтських воркерів агенції; його змінює лише
платформна команда окремим PR. `app/scripts/`, `materials/`, `.coderabbit.yaml` і
`.github/` — умови завдання й перевірки. Зміна будь-якого з них ламає або інші
проєкти, або саму перевірку.

## Правило

- НЕ створюй, не редагуй і не видаляй файли в:
  - `app/src/core/**` — жодних «дрібних фіксів» і «одного нового типу»;
  - `app/scripts/**` — перевірка правил і `core.lock.json`;
  - `materials/**`, `.coderabbit.yaml`, `.github/**`.
- Винятків немає. Якщо задачу неможливо виконати без зміни core — **зупинись**:
  опиши, що саме і навіщо треба змінити в core, і чекай рішення людини.
- Потрібна функція, якої немає в API ядра (див. `.claude/rules/architecture.md`) —
  пиши її в модулі, який її використовує, а не в core.

## Як перевірити

- `git status --short -- app/src/core app/scripts materials .coderabbit.yaml .github` → порожньо.
- `cd app && npm run check:rules` → у рядку `core-untouched` стоїть 0.
