# Конвенції коду lead-sync

## Контекст

Кожна конвенція нижче — наслідок аварії, а не смаку. `postJson` з'явився після
ночі без таймаутів, `log.redact` — після токена у відкритому журналі,
`parseJson` з guard — після нічного інциденту 10.09.2026, де тихий fallback
на «значення за замовчуванням» дав дев'ять годин дублікатів
(`materials/error-log.txt`). `npm run check:rules` перевіряє п'ять із цих
правил статично.

## Правило

1. **Помилки — це значення.** Функція, що може не вдатися, повертає
   `Result<T>` з `core/types.ts`. Інтеграція не кидає винятків назовні:
   `send()` завжди повертає `Promise<Result<void>>`.
   Не `throw` — `return { ok: false, error: "..." }`.
2. **Вихідний HTTP — лише `postJson()`** з `app/src/core/http.ts` (таймаут,
   повтори на 5xx/429, маскування URL у журналі).
   Не `fetch(...)`, не `axios`/`got`/`ky`, не `node:https` — `postJson(url, body)`.
3. **Змінні середовища — лише `readEnv()`** з `app/src/core/config.ts`.
   Не `process.env.X` поза `core/config.ts` — `const v = readEnv("X"); if (!v.ok) return v;`.
   Значення секрету не потрапляє ні в журнал, ні в код, ні в тест.
4. **Зовнішнім даним не довіряємо.** Будь-який JSON — відповідь API, тіло
   вебхука, файл стану — розбирається через `parseJson(text, guard)` з guard
   на очікувану форму (`isRecord`, `isString`, `isNumber` з `core/parse.ts`).
   Не `JSON.parse(...)`, не `try { ... } catch { return DEFAULT }` —
   невалідний вхід повертає `Result` з `ok: false`, і це видно в журналі.
   **Тихо підставити значення за замовчуванням не можна**: так пошкоджені дані
   стають непомітними (див. `materials/error-log.txt`).
5. **Журнал — лише `log`** з `app/src/core/log.ts` (`log.info` / `log.warn` /
   `log.error`). Не `console.log` — він друкує токени як є, `log` їх маскує.
6. **Без `any`.** Не `: any`, не `as any`, не `<any>` — `unknown` плюс guard
   з `core/parse.ts`.
7. **Без нових залежностей.** У застосунку нуль runtime-залежностей.
   Не `npm install <пакет>` і не рядок у `dependencies` — напиши потрібні
   ~20 рядків на стандартній бібліотеці або постав питання в PR.
8. **Мінімізація даних.** У сповіщення (Slack, Telegram, будь-який месенджер)
   ідуть лише `name`, `source`, `budgetUsd`. `lead.email` і `lead.phone` у
   тілі повідомлення месенджера — **дефект**, а не деталь: повні дані йдуть
   тільки в системи обліку (таблиця, CRM).
9. **Імена.** Файли — kebab-case; поле `name` інтеграції збігається з іменем
   файлу без розширення (`sheets-append.ts` → `name: "sheets-append"`).

**Тести (Vitest, `*.test.ts` поруч із модулем).** Реальної мережі немає:
`vi.stubGlobal("fetch", ...)`, змінні — `vi.stubEnv`. Для кожної інтеграції —
три випадки: успішна відправка (перевірити URL **і тіло** запиту), відсутня
змінна середовища, помилка від зовнішньої системи.

**Спадковий код** переписують окремою задачею й **без зміни поведінки**, яку
фіксують тести: URL, тіло запиту, тексти помилок лишаються ті самі. У цьому
репозиторії його вже немає: `sheets-append.ts` приведено до конвенцій
командою `/refactor`, а `sync/state.ts` — разом із фіксом нічного інциденту.
`check:rules` має лишатись **TOTAL: 0**; будь-яке нове число — це регрес.

## Як перевірити

```bash
cd app && npm run check:rules   # п.2-6: рядки http-via-core, env-via-config,
                                # json-via-parse, log-via-logger, no-any, no-new-deps
cd app && npm test              # 18 тестів зелені; після рефакторингу — ті самі 18+
cd app && npm run typecheck     # п.1: send() без Result<void> не скомпілюється
```

Пункт 8 машина не ловить — перевіряй очима: у тілі запиту до месенджера не
має бути `lead.email` чи `lead.phone`. На старті домашки `check:rules` показував
**TOTAL: 8**, зараз — **0**. Будь-яке число більше нуля тепер означає регрес.
